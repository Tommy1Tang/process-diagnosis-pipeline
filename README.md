# process-diagnosis-pipeline

> **A process-diagnosis skill for FDEs and pre-sales engineers.** Turns a client complaint into an auditable proposal — built on Rummler-Brache's *Improving Performance*, extended with an **AI onboarding** track for deciding what may be handed to an agent.

把"客户抱怨"变成"可验收方案"的流程诊断流水线。它不产出流程图鉴赏，只产出三样东西：**哪一格坏了、哪一步漏钱、哪个数字能验收。**

基于 Rummler-Brache《流程圣经》（绩效三层 × 流程层空白地带），为 FDE / 售前工程师 / SAP 业务顾问设计，作为 agent skill 使用。

---

## 它解决什么

| 客户/老板的说法 | 这个 skill 的回应 |
|---|---|
| "交付慢、库存高、质量不稳、设备老停" | 先画 IS，再找断点，不给没号脉的方案 |
| "上了系统没人用" | HPS 六问：80% 是环境问题，不是员工素质 |
| "提升 30% 行不行" | 没有基线不承诺收益，说不清"现在多少"就不写目标 |
| "我们想上个 AI" | D 轨道：五类断点里只有一类该交给 AI |

## 六阶段

```text
① 定方向  症状 → 3 个 CBI（每个带基线/目标/口径/责任人）
② 画现状  端到端泳道图（第一遍不标断点）
③ 找断点  五类：多余 / 缺失 / 顺序错 / 说不清 / 指错，每条算年化影响
④ 重设计  六动作：消除 → 简化 → 合并 → 并行 → 质量内置 → 授权/自动化
⑤ 锁指标  M1（端到端）→ 倒推 M2 → 少量 M3，M2 必须挂到 M1
⑥ 交制度  流程责任人 + 四节律 + 仪表盘，回答"第 91 天谁在看哪张表"
收尾      三张纸：诊断页 / 流程页 / 价值页
```

每阶段都有门禁，不过不许往下走。

## 四条铁律

1. **未画 IS 不出方案。** 方案阶段之前出现"建议"字样即为违规。
2. **指标不挂 M1 不进价值页。** 追不到端到端指标的数字，一律删。
3. **HPS ①–④ 未答不提培训。** 标准、资源、奖励、反馈没查清，不许把系统问题推给员工。
4. **五类断点只有"说不清"类可以交给 AI。** 多余→删、缺失→补、顺序错→重排、指错→修指标。

## D 轨道：AI 上岗（v2）

独立轨道，不是第七阶段。它吃断点清单（可来自阶段 3，也可客户直接给），**不重画流程**。

```text
D-① 判定   这条断点能不能交给 AI？（五问否决制）
D-② 规则   交给 AI 之后怎么写？（规则卡 + 三类反例）
D-③ 放权   observe → auto 怎么放？（四档阶梯 + 退回机制 + 三条红线）
D-④ 观察   看什么、误判怎么分类（待补）
D-⑤ 验收   数据挂回 M3（待补）
```

### D-① 五问否决制

任一问不过即否——不是打分，没有"3.5 分也能上"的空间。

| 顺序 | 问题 | 判据 |
|---|---|---|
| ① | 这活该不该存在 | 去掉它流程还跑得通 → 是"多余"，归消除 |
| ② | 量够吗 | 每周 < 5 次 → 观察期攒不出数据 |
| ③ | 能写成条件吗 | **两个现在做这事的人，会不会做出同样的判断？** 不会 = 口径没统一 |
| ④ | 判断要素拿得到吗 | 数据在哪个系统、谁授权 |
| ⑤ | 错了能撤吗 | 不可撤（付款/合同/合规）→ 只能出建议，不能执行 |

第 ③ 问是整个工具最狠的一句：用"结果一致性"反推"口径一致性"，比问"你们有标准吗"可靠得多。

### D-③ 四档阶梯

| L0 影子 | L1 建议 | L2 执行+通知 | L3 静默 |
|---|---|---|---|
| 只记录 | 给人确认 | 自动做，告诉人 | 只写日志 |

**大多数场景该停在 L2**——"通知"本身就是一层安全网。放权可以在三个维度上各放一半：规则 × 通道 × 人群。

三条永不 auto 的红线：不可撤回的动作、合规责任判断、影响面不可控。

## 怎么用

三种模式，按你要什么选：

| 你要什么 | 模式 | 产物 | 时间 |
|---|---|---|---|
| 只想搞清"问题大概在哪" | **A 速诊** | 九格红黄绿 + 3 条断点 + 1 指标 | 30 分钟 |
| 要一份方案给客户/领导 | **B 标准** | 六阶段全套 + 三张纸 | 半天–2 天 |
| 要签合同/按结果收费 | **C 交付级** | B + 基线采集 + 验收条款 + 治理 | 3–5 天 |
| 已有断点，判断能不能上 AI | **D AI 上岗** | 适配判定 + 规则卡 + 放权检查表 | 1 小时起 |

交付前自检：

```bash
python scripts/check_package.py <诊断包目录>
```

## 设计取舍

- **诊断先于方案。** 没有 IS 就没有 SHOULD。这条挡掉的是"我一看就知道你们该上 MES"。
- **没有基线不承诺收益。** 给区间也不要给精确值；宁可标 `[待采集]`。
- **没有责任人不做项目。** 方案在验收后 90 天归零，因为没人每月看那张表。
- **AI 只接"说不清"。** 把不该存在的环节自动化，是用工具固化浪费。
- **删掉的比加上的多。** 规则越少越稳；第一轮开 auto 的规则不超过 1 条。

## 已知局限

诚实标注，免得当成标准：

- **两个阈值是拍的，不是测的**：D-① 的"每周 ≥ 5 次"、D-③ 的"2 周 / 30 条 / 80%"。低频高价值场景（设备大修决策）需要按场景调，调的理由要写下来。
- **D-④ / D-⑤ 尚未定型**：观察期周报与验收叙事，需要真实项目的 Decision 记录才能写准，目前留空。
- **`check_package.py` 的顺序校验只认表格的「动作」列**：既不写成表格、也不写成 `- 消除 …` 列表时，无法校验顺序，只会 WARN 提示。这是刻意的——宁可漏检，不误报。
- **断点库偏制造业**：24 条断点来自离散制造 + SAP PP/QM/PM 场景，服务业要自己补。
